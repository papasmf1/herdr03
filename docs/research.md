# 서울 문화행사 찾기 — 데이터 출처 조사

작성: product-research (자료 조사) · 2026-11-05
의뢰: qitem-20261105020424-e0f2e4412efd1c80 (product-lead)

## 1. 결론 (요약)

- **출처**: 서울 열린데이터광장 「서울시 문화행사 정보」, Open API 서비스명 `culturalEventInfo`. 공공누리 제1유형(출처 표시).
- **실시간 호출은 인증키가 있어야 한다.** 샘플키(`sample`)는 **최대 5건**(위치 1~5)만 준다. 실습은 키 없이 가능하다.
- **브라우저에서 직접 호출은 안 된다.** 응답에 CORS 헤더(`Access-Control-Allow-Origin`)가 없고, 주소가 `http://…:8088`이라 HTTPS 페이지에서는 혼합 콘텐츠로 막힌다. 앱은 **서버(`server.mjs`)가 받아서 `/api/events`로 넘기는 구조**를 유지해야 한다.
- **앱의 기본 데이터는 저장소의 스냅숏 `data/events.json`(323건, 2026-10-31 사본)이 적합하다.** 이미 실제 응답이다. 이번 작업에서 만든 `data/events.sample.json`(60건)은 그 스냅숏에서 고른 부분집합이다. 합성 데이터는 넣지 않았다.
- **보안 문제 1건**: `scripts/fetch-events.mjs` 6행에 인증키가 **코드에 하드코딩**되어 있다. §6 참고.

### 2-1. 실제 호출 결과 (샘플키 `sample`, 2026-11-05)

| 요청 | 결과 |
|---|---|
| `http://openapi.seoul.go.kr:8088/sample/json/culturalEventInfo/1/5/` | 200, `INFO-000`, 5건 반환 |
| `…/1/100/`, `…/1/1000/`, `…/6/10/`, `…/101/200/` | `ERROR-335` "샘플데이터(샘플키:sample)는 한번에 최대 5건을 넘을 수 없습니다. 요청시작위치와 요청종료위치 값은 1 ~ 5 사이만 가능합니다." |

## 3. 응답 필드 (실제 값으로 확인)

필드 25개. 값은 실제 응답(샘플 5건) 또는 스냅숏 `data/events.json`(323건)에서 가져왔다.

## 4. 앱 필터 규칙 제안 (구현자 참고)

- **구**: `GUNAME` 정확 일치. 빈 값은 "기타/미분류"로 묶거나 목록에서 뺀다.
- **무료**: `IS_FREE === '무료'`. 값이 `무료`/`유료` 둘뿐이라 단순 비교로 충분하다(323건 확인).
- **날짜**: 행사 기간 `[STRTDATE, END_DATE]`가 선택한 날짜와 겹치는지로 판단. 날짜 형식은 `'YYYY-MM-DD HH:MM:SS.0'`이라 앞 10자를 잘라 `YYYY-MM-DD`로 비교하면 된다. `END_DATE`가 기준일보다 이전인 행사는 스냅숏 기준으로 0건이다.
- **필터 조합**: 세 필터 AND.

## 5. 데이터 품질 문제 (스냅숏 `data/events.json` 323건 기준)

| 문제 | 건수 | 대응 |
|---|---|---|
| `END_DATE`가 비정상적으로 먼 미래 (`2626-08-08`, `2099-12-31`) | 2건 | 원본 그대로 두고, 표시 시 "상시/기간 미정"으로 처리하거나 샘플에서는 제외(샘플은 제외함) |
| `GUNAME` 빈 값 (`공공미술 시민아이디어 구현 서울대공원 <솜사탕코끼리> 시민개방`) | 1건 | "기타" 처리 |
| `IS_FREE === '무료'`인데 `USE_FEE`에 금액이 적힌 행 | 55건 중 대부분은 "무료", "0원", "전석무료"지만, `30,000` 같은 금액이 섞인 행 1건 확인 | `IS_FREE`를 기준으로 쓰되, 카드 요금 표시는 `USE_FEE` 원문을 보여 준다. 필요하면 조사 대상으로 남긴다 |
| `DATE`와 `STRTDATE`/`END_DATE` 중복 | 전 건 | 날짜 필터는 `STRTDATE`/`END_DATE` 하나만 쓴다 |
| 스냅숏 기준일이 2026-10-31 | 전 건 | 앱 화면에 "기준일"을 명시(screen-design.md 기준) |
| 중복 (`TITLE`+`DATE`) | 0건 | — |
| `MAIN_IMG`/`LAT`/`PLACE`/`TITLE` 빈 값 | 0건 | — |

- README.md:85 는 "11월 이후 끝나는 행사 293건"이라고 적었지만 실제 파일은 323건이다. 차이는 아직 설명되지 않았다(사본 생성 기준이 다를 수 있음). 앱 동작에는 영향 없음.

## 6. 보안: 하드코딩된 인증키 (조치 필요)

- `scripts/fetch-events.mjs:6` 에 **16자 인증키 문자열이 상수로 들어 있다**. README.md:76-78 은 키를 환경변수(`SEOUL_API_KEY`)로 넣으라고 안내하고, README.md:81 은 "키는 코드나 커밋에 넣지 마세요"라고 적었다. 코드가 자신의 안내를 어기고 있다.
- 이 키를 이번 조사에서 사용하지 않았다. 키 값은 이 문서에 옮기지 않았다.
- 권장: (a) 상수를 지우고 `process.env.SEOUL_API_KEY`만 쓰게 한다. (b) 이미 공유된 저장소라면 이 키를 재발급한다. 이 저장소는 git 저장소가 아니어서(`.git` 없음) 이력 검사는 하지 못했다.
- 이 문제는 build 담당이 고치거나, 사용자가 판단해야 한다. 조사 범위 밖이라 고치지 않았다.

## 7. 대안 출처 비교 (짧게)

- **서울 열린데이터광장 culturalEventInfo (채택)**: 실제 서울 문화행사 전체, 원본 구·날짜·무료 필드 제공. 인증키 필요, 호출은 서버에서만.
- **서울 문화포털 웹 (culture.seoul.go.kr)**: 상세 링크 대상. API 아님, 스크래핑은 약관·구조 변경 위험이 커서 비권장.
- 이번 조사에서 다른 공개 API 후보는 확인하지 않았다. 필요하면 추가 조사하겠다.

## 8. 권장안

1. **기본 데이터**: 저장소의 `data/events.json`(스냅숏)을 서버가 `/api/events`로 돌려주는 현재 구조를 유지한다. 키 없이 실습이 된다.
2. **샘플**: `data/events.sample.json`(60건)은 실제 행으로 구성되었고, 25개 구·무료 34건/유료 26건·단일 날짜 5건/기간 55건을 포함한다. 화면 테스트에는 충분하다. 단, 샘플은 스냅숏의 부분집합이라 실제 필터 결과의 분포를 대표하지는 않는다.
3. **실시간 갱신**: `fetch-events.mjs`를 쓰되, 키를 환경변수로만 받게 고친 뒤 사용한다. 실제 키 발급은 사용자의 계정 행위이므로 이번에는 하지 않았다.
4. **브라우저 직접 호출은 하지 않는다**. 반드시 서버를 거친다.

## 9. 막힌 것 / 미확인

- 실제 일반 인증키로 1,000건 페이지 호출을 확인하지 못했다(사용자 계정 필요).
- OA-15486 데이터셋 페이지를 직접 열어 확인하지 못했다(검색 결과에 없음).
- 스냅숏(2026-10-31)과 현재 공개 데이터의 차이는 확인하지 않았다.
- `data/events.sample.json`은 2026-10-31 스냅숏에서 가져온 행이므로 그 뒤에 바뀐 행사 정보는 반영되지 않았다.
